# Tixi Voice 1.1 — executed tests and limitations

Date: 2026-09-23. All voice references used for these checks were synthetic Piper output. No real user recordings, profiles, history, model weights or test outputs are included in the distribution.

## Environment and actual build

- Windows CPython 3.13.14 x64, PySide6/Qt 6.8.3, Piper 1.8.0, NumPy 2.2.6, CPU ONNX Runtime 1.23.2, whisper.cpp 1.8.6; Windows binaries executed under Wine 10/Xvfb on Linux. PyInstaller 6.22.3 built the real PE32+ x64 GUI EXE and its onedir runtime.
- The Linux environment had roughly 1.9 GiB total memory available to it and two CPU cores. This is NOT a minimum RAM specification for native Windows. Available memory varied across tests. There was no physical NVIDIA/AMD/Intel GPU or audio input/output device for validation.
- Native Linux CPU inference was also run with ONNX Runtime 1.24.4. The bundled Windows CPU library stays at 1.23.2; optional DirectML 1.24.4 is isolated, not installed over that library.
- A verified native Microsoft UCRT was used to fill Wine's missing complex-number functions. It is not distributed as a Wine/system DLL; Windows 10/11 supplies its own UCRT.
- The EXE is unsigned, portable/onedir, not an installer, and not claimed byte-for-byte reproducible.

## New automated and integration checks

1. **26 unit tests passed under Windows Python/Wine and native Python.** Existing coverage includes history/settings, atomic writes, model integrity/local installation, cancellation, path safety, text bounds, SRT parsing and audio preprocessing. New coverage includes schema-1 backup/migration, preservation of old history/settings, consent-required profiles, managed profile deletion, retaining a row after deletion failure, profile path/embedding validation, reference duration/silence rejection, reference cancellation, spectrum shape/dtype, WAV metadata without changing audio frames, conservative RAM/GPU plans, simulated failed GPU job retrying once on low-memory CPU, cancellation without retry, archive traversal rejection and optional-runtime cleanup on model deletion.
2. **Real CPU enrollment and personalized speech:** native Linux generated a 19.33-second Persian Piper reference, created a local profile and produced a 6.29-second personalized English WAV. Sample rate, duration, finite/nonzero samples and AI metadata were checked. This was functional conversion, not a human-identity similarity test.
3. **Windows Qt source GUI:** guided reference/profile page, consent rejection before enrollment, real profile enrollment and personalized English output, dark/light themes, normal/small layouts, profile selection/deletion, result history and audio metadata were exercised. Recording ownership/stop routing was tested with simulated input; it did not test a physical microphone. Screenshots were inspected.
4. **Actual frozen workers from Persian-named installation and data paths:** English-reference enrollment, personalized Persian and English, very short text and multi-block Persian output all passed. Example executed outputs: Persian short greeting 0.476 seconds, English short greeting 0.534 seconds, and a 621-character Persian passage 47.156 seconds. The latter took approximately 76.4 seconds including base synthesis/conversion in this test environment. These are test-run observations, NOT promised speeds. Frame counts matched the expected duration, samples were finite/nonzero, and the AI RIFF comment was present. A shorter repeated multi-block run completed the full test harness successfully.
5. **Optional runtime in the actual frozen worker:** CPU probe resolved to bundled ONNX Runtime 1.23.2; DirectML probe resolved to the separately extracted 1.24.4 package in a Persian-named data path and advertised DmlExecutionProvider/CPUExecutionProvider. This verifies extraction, import and separation, NOT hardware acceleration or GPU kernel execution. Real GPU execution remains untested.
6. **Actual frozen GUI:** startup, existing profile selection, English personalized generation through its own frozen child, waveform/result controls, artificial-voice labeling, database persistence, My Voice navigation and normal close passed. A 4.075-second personalized result was saved to local history. application.log remained empty and the data lock was released.
7. **Existing speech-recognition regression:** the bundled Windows whisper.cpp/Base engine transcribed the generated English reference from Persian-named installation/data paths, producing text and timing segments. It made word errors (for example, “Hello”/“Allow”); this is not an accuracy benchmark.
8. **Global dictation (new in this build):** `RegisterHotKey` with Ctrl+Shift+Space was verified to deliver WM_HOTKEY through Qt's native event filter — an injected key press reached the registered path without manual message posting. Hold-to-talk kept a real WAV growing while the key was held (0.25 s → 3.76 s) and the temporary file was removed afterwards, on both the source run and the deployed EXE. `SendInput` typed Persian and English text ("سلام دنیا! Hello 123") correctly into a focused window. The floating overlay was screenshotted over a busy moving background and pixel-checked: the pill interior stays opaque (no background bleed), the waveform renders, and the overlay is topmost, click-through and never takes focus. The deployed EXE kept holding the hotkey while other applications ran; application.log stayed empty.
9. **Themes and voice effects:** the appearance tab switches all ten palettes without errors, the selection persists across restart, and the dictation overlay recolors with the active palette. Each voice-effect preset renders a non-empty WAV; the unchanged 26 unit tests still pass.

The original v1.0 release also exercised real Persian/English Piper + Whisper Small round trips, frozen TTS/STT GUI flows, actual Windows HTTPS model-file checksums and partial-download resumption, bounded child-process cancellation, and a simulated microphone callback/queue writer. These are historical baseline checks, not a claim that every large model or device was re-tested in v1.1.

## Important unverified behavior / no guarantees

- No native Windows installation or physical GPU was available. Wine success and provider discovery do not prove compatibility with every device/driver or demonstrate GPU speed. Automatic GPU fallback logic has simulated-failure coverage; real device-loss/OOM on NVIDIA/AMD/Intel is unverified.
- No physical microphone, speakers, headphones, USB/Bluetooth audio, Windows microphone permissions or acoustic playback evaluation was available. Device switching, recording quality and actual voice similarity need checking on the user's machine.
- Personalized output is experimental tone-color transfer. Piper retains pronunciation/rhythm; exact voice identity, accent, emotion, cross-language quality and naturalness are not guaranteed. The reference checks are simple energy/clipping checks, not identity verification or robust speech detection.
- The WAV notice is removable metadata, not an audible/tamper-resistant watermark. Local profile samples/embeddings and history are not encrypted.
- No full 10,000-character personal-voice stress run, 90-minute STT run, Medium-model benchmark, statistical accuracy study or exhaustive concurrency/corrupt-driver test was performed.
- Full 177-MiB package download through the final EXE GUI was not an end-to-end network test. Exact files were downloaded and hash-verified in QA, local model handling was tested, and the optional runtime was actually loaded by the EXE. Models/runtime are never silently fetched by inference.
- Native batch-file builds on Windows, sleep/resume, hot-unplug, high-DPI multiple monitors, accessibility, unusual corporate proxies, antivirus/SmartScreen reputation, code signatures, ARM64/32-bit and Windows 7/8 remain unverified or unsupported targets.
- No STT model was installed in the current test environment, so the dictation record → transcribe → type round trip was never completed with real speech recognition. The no-model error path, language auto-detection and typing into elevated (administrator) windows remain unverified end-to-end.

## Suggested first-run checks

1. Close v1.0, back up the entire data folder, and extract v1.1 into a separate program folder. Keep _internal beside Tixi-Voice.exe. Do not mix old/new runtime files.
2. In Models, download one Piper voice and the personal-voice package, or import their exact pinned files from a folder. Read the optional executable-runtime confirmation.
3. Disconnect the network. Open My Voice, read the displayed text naturally for 20–45 seconds, stop, listen to the reference, enter a name, confirm ownership/permission and create a profile.
4. In TTS, select the correct language and profile. Generate a short sentence, listen and export WAV. Compare ordinary voice vs personal profile without expecting a perfect identity match.
5. If necessary, choose low-memory mode, close other apps and retry. Check the reported CPU/DirectML provider. Resetting the GPU cooldown only schedules another attempt; it does not certify support.
6. Restart and confirm profiles/history persist. Delete a disposable profile and confirm old exported/history WAVs remain, as documented. Temporary unregistered recordings are intentionally removed.
7. Check ordinary TTS and STT, TXT/SRT export, edit behavior and local history as before. Test cancellation and disk/read-only errors only with disposable data.
8. Enable dictation in STT, focus any text field in another application, hold Ctrl+Shift+Space, speak and release. Confirm the text lands in that field, the overlay appears/disappears, and the status bar reports success or the missing-model error.
